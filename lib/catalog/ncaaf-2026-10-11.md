# NCAAF trend catalog — 1,050 named directions

Prepared October 11, 2026, Eastern Time. Definition version: catalog-2026-10-11-v1.

This catalog contains **525 paired base rules / 1,050 separately named directions**, plus **117 exact subset filters** and **24 worked combined-subset definitions**. Both sides of every pair have an explicit selection. The new rules are hypotheses to track; no performance has been calculated for them in this catalog and none is certified as profitable.

The core aim is complete coverage of observed NCAAF full-game spreads and totals, including quieter games. Every available market enters a baseline ledger. Missing observations remain missing; they do not become wins, losses, or neutral movement. Player props, moneylines, and other sports are outside this catalog.

## Shared definitions

| Symbol | Exact meaning |
|---|---|
| D / final decision | Actual saved observation closest to 15 minutes before archived published kickoff, inside the inclusive 10–20 minute pregame window; ties choose the later observation. Never substitute an observation after kickoff or carry an older one into this window. |
| O / opening | First saved usable paired quote in the retained same-source history. For split movement it must include genuine opening ticket shares strictly between 0% and 100%. Line and split fields come from that same observation. It is the first saved usable quote, not a verified original sportsbook opener. O must precede D. |
| s / anchor / opp(s) | s is the signal side identified by the trigger. Its opposite is the other spread team or the other total direction. When a trigger supplies Home, Over, or favorite f instead, that is its explicit anchor. In a cross-market total rule, s/f in a spread condition is a context team; the total anchor for filters is the explicitly selected total direction. |
| L0(s), Ld(s) | Signed opening/final spread for team s. A negative final spread denotes a favorite; a positive one denotes an underdog; zero is pickem. |
| T0, Td | Opening/final full-game total. Over and Under must use the same quoted total for exact mirror grading. |
| m(s) | Support in point units: L0(s) - Ld(s) for spreads; Td - T0 for Over; T0 - Td for Under. Positive means the quote moved toward that side. This definition describes market direction, not an improved price for that bet. |
| b0, bd / h0, hd | Actual opening/final ticket percentage / money percentage for a side. These are shares, not counts or dollar amounts. Only fields explicitly required by a rule are required for that rule. |
| P(s), H(s) | bd(s) - b0(s), and hd(s) - h0(s), in percentage points (pp). |
| G0(s), Gd(s) | h0(s) - b0(s), and hd(s) - bd(s), in pp. The Sharp name describes this proxy only; it does not identify professional bettors. |
| Rstake(s) | [hd(s)/bd(s)] / [(100-hd(s))/(100-bd(s))]. Requires both ticket and money percentages strictly inside 0–100 and a common underlying market sample. |
| Q30, Q60, Q120, Q360, Q1440 | Actual latest observation at or before kickoff minus 30/60/120/360/1440 minutes, no more than 5/10/15/30/60 minutes older than that target, respectively. Required observations must precede D and stay within one source history. A missing Q is not filled using a later observation. |
| m_between(s,A,B) | Signed point support over the actual earlier A to later B interval, using the same side convention as m(s). bQ and hQ are actual shares at Q. |
| Path statistics | Compute max/min support, lines, shares, and gaps using only actual observations from O through D. A support increment is the change in cumulative support from one saved quote to the next. Remove zero increments before counting direction reversals. Before_D excludes D itself. |
| p(s) | Price-implied percentage: 100*abs(A)/(abs(A)+100) for American A <= -100; 100*100/(A+100) for A >= +100. Reject invalid American prices. |
| nvp(s) | No-vig quoted probability percentage: 100*p(s)/(p(s)+p(opp(s))). Requires actual contemporaneous prices for both sides on the same spread or total. |
| f | Team with the negative final spread at D. Exclude pickem where a favorite is required. |
| Calendar / rest | All kickoff weekdays and display-time buckets use America/New_York. Rest uses calendar-date difference between this kickoff and the immediately prior completed game; do not invent a rest value for season openers with no eligible prior game. |

## Matching, opposite sides, and data quality

1. A pair uses the same trigger, same physical game, same market, and same final quote for both directions. Opposite does not mean applying a different trigger to different games.
2. Where s is found by testing both sides, require exactly one matching anchor. If both anchors match (possible for injury or prior-performance conditions), mark that directed rule ambiguous and retain the game in its baseline/context records. Do not arbitrarily pick a team. Rules that explicitly supply Home, Over, or another fixed anchor are unambiguous.
3. Resolve team aliases to a physical event ID first. Emit no more than one entry per event + market + pair ID + direction. Several different subsets may match a game; their ledgers overlap and cannot be added together to make an overall EZPZ record.
4. Exact spread opposites require equal-and-opposite paired spreads; total opposites require the same total. Paired source quotes must be from the same collection batch, or from observations at most 60 seconds apart. Conflicting lines, market identities, source changes, or materially inconsistent side percentages are flagged, not synthesized. Each rule grades at the designated source-book final quote; choose the source-book policy before reviewing outcomes.
5. Share percentages must be finite and inside 0–100. When both sides are supplied, ticket sums and money sums must each be within 2 pp of 100. Opening shares used for growth must be strictly inside 0–100; final endpoint extremes remain tagged as reported. Price/path/volume signals additionally require their actual underlying inputs.
6. A label from an old published play cannot stand in for missing ticket, money, line, volume, or timestamp data. Do not manufacture percentages or movement from the label.
7. Current football policy defaults missing execution prices to -110. Retain the observed-price-missing flag separately. That default cannot create a price movement signal or a verified historical profit calculation.
8. For games before September 21, 2026 use retained original legacy observations; from September 21 onward use ScoresAndOdds. Never connect opening and final endpoints from different feeds.
9. New numeric cutoffs here are proposed fixed definitions, chosen for readable tracking bands rather than fitted to outcomes. Several aggregates and ranges intentionally overlap. Same-trigger aliases, such as opposing-side ticket decline versus ticket growth, are not counted again as independent patterns.

| M | Projection archived before D, plus the market fields named by the rule | 22 |
| R | Earlier completed results, their historical lines where needed, and timestamps | 20 |
| S | Schedule / venue / season context frozen at D; may require additional metadata | 22 |
| K | Archived poll or season classification available before D | 10 |
| W | Archived kickoff forecast / roof status saved before D; additional input needed | 14 |
| I | Archived personnel roles and official availability saved before D; additional input needed | 16 |
| X | Additional raw book-level or absolute-volume data; not inferable from split percentages | 18 |

Codes identify the principal data dependency, not permission to omit other fields named in a trigger. B/E/H/P describe data already of the kind used by the existing quote/split system, but actual historical coverage still has to be checked. M/R/S/K/W/I/X are explicitly dependent on archived model, result, context, forecast, personnel, or additional-provider inputs; availability is not assumed. A cross-market rule requires both source markets at D.

## Tracking records and the above-60% gate

- Track W, L, P, settled count, win percentage W/(W+L), and the last seven settled entries. Show pushes separately; exclude pushes from the win-percentage denominator. A 0–0 or push-only record is unrated.
- The agreed provisional eligibility rule is strictly above 60%, with no 50-bet minimum. At 60% or below, a type stops supplying EZPZ candidates but continues accumulating all eligible signal results.
- Track both all-history-to-date and forward results since each definition was frozen. New discoveries do not become historical posted EZPZ bets. Show the sample size prominently even for a 1–0 provisional qualifier.
- For historical replay, determine each type's eligibility using only settlements known before that game's D. A later final score cannot affect an earlier pick; same-day games still in progress are not settled evidence.
- Freeze definition version, source, entry quote, matched memberships, and the qualifying record as of D. Historical membership cannot be rewritten when a definition changes; create a new definition version.
- Evaluate all matching signals before applying the final one-pick-per-game EZPZ priority. Keep standalone signal records separate from the actual chosen-pick ledger. Overlapping tags do not imply independent agreement.
- If different qualifying subsets recommend opposite sides of one market, surface that conflict. This catalog does not invent a conflict-resolution policy or alter the current selection priority.
- W/L opposite records complement each other on an identical settled cohort and line, excluding pushes. A 55% follow record implies a 45% fade record. A type falling below 60% does not by itself mean its opposite exceeds 60%.

The verified NCAAF Public Fade rule is >75% tickets with at least a 55 pp ticket-minus-money gap; the simple 80% public rule is a separate proposed type. The money-momentum condition uses the existing NFL thresholds as a proposed NCAAF extension, not as a claim that it is currently deployed for NCAAF.

This is a definition catalog, not a fresh backtest, an implementation, or a deployment. No new win records are asserted. Hundreds of overlapping comparisons can produce favorable historical slices by chance; preserve the complete catalog, samples, and later forward results. [NIST multiple-comparison guidance](https://www.itl.nist.gov/div898/handbook/prc/section4/prc47.htm) explains why repeatedly examining individual comparisons does not preserve the overall confidence level of a single comparison.
