# NBA ScoresAndOdds integration

The authenticated `/api/cron/nba-market` route reuses the existing ScoresAndOdds NBA consensus parser and shared market refresh policy. Vercel invokes it every five minutes; durable state skips source collection until 30 minutes have elapsed outside the 90-minute tipoff countdown. Inside the countdown it collects every five minutes. A new Eastern date forces an initial refresh.

Bind both spread sides and both total sides to the exact current ESPN NBA regular-season schedule. Match names through the scheduled teams' complete name, nickname, city and abbreviation, preserve canonical team names and ESPN game IDs, and reject conflicting or incomplete pairs. All spread/total prices are explicitly assumed -110. No sportsbook line is replaced by a model projection.

The NBA namespace uses the same dataset names and core columns as football: `schedule`, `posted_games`, `weekly_market_trends`, `odds_snapshot`, `public_split_snapshots`, and `refresh_state_market`. Current lines retain first-observed lines and percentages, later percentage changes and movement history. A complete observation 10–20 minutes before tipoff becomes immutable `FINAL_PREGAME`; late observations never manufacture a missed final snapshot. Completed games and historical observations are retained under their original Eastern date.

Writes read only affected dates and execute atomic, identity-bound inserts/updates. Allocate one-based contiguous dataset positions inside the write lock. Unchanged payloads produce no row or manifest writes; archives append only changed states and final locks. Identity indexes stay out of ordinary freshness updates. No full-season archive replacement or scan runs on a public page request. The existing sports' writer and namespace behavior remains unchanged.

`/api/nba-public-data` is read-only and cached at the CDN for 30 seconds. It reads the selected date's schedule, current/final split rows, and compact recent research forecast summaries. Opening and near-tipoff forecast versions remain separate. The NBA board shows actual market lines and percentages, expandable movement history, model-versus-market edges and saved grades, and observed result outcomes. Source collection, fitting and model builds never run on a public read. NBA team trends, signals and public pick publication are separate future work.

The paired Python admin change requires a complete, fresh ScoresAndOdds quartet before automatic forecast preparation/locking. It archives those exact lines, uses assumed -110 pricing, and derives research A/B/Lean/Pass grades through the shared basketball grading helper. NBA uncertainty is a normal approximation from the selected model's frozen 399-game January–February validation errors; it is explicitly not a calibrated win probability. Old line-free forecasts are never assigned later lines or retroactive grades.

Verification: `node tests/nba-market.cjs`, `npx tsc --noEmit`, and `npm run build`. The behavioral checks exercise actual SQL against SQLite, source identity/completeness, refresh cadence, frozen final quotes, no late locks, incremental writes, repeat-write suppression, rollback, isolation from NFL, saved-only public reads and settlement signs. The live source check on October 22 matched both NBA games and all eight spread/total sides.
